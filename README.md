## What this probe tests

uv 0.12.15 fixed a regression that caused `uv pip install --system`
and `uv pip install --target <dir>` to be incorrectly rejected. The
Mend Unified Agent (UA) shells out to these two install modes when
it invokes uv to resolve or install project dependencies before
scanning. On affected pre-0.12.15 builds the flag rejection caused
the install step to fail, resulting in an empty dependency tree (0
packages resolved).

This probe validates that:

1. The standard `uv.lock`-driven detection path is not blocked by
   the flag rejection (Mend reads `uv.lock` directly via its pip-
   compatible resolver — the flag fix restores the pre-step install,
   not the lockfile parse itself).
2. All direct and transitive packages resolve correctly from
   `uv.lock`, producing a 3-level graph with shared transitive
   dependencies (`certifi` reachable via both `requests` and
   `httpx`).
3. Mend does not silently return an empty tree when the install
   command is rejected; it should surface a scan error if the
   pre-step fails.

## Mend config

Bucket B — no `.whitesource` emitted.

Python version is dynamically detected by Mend from `.python-version`
(which takes precedence over `pyproject.toml`). The uv tool itself is
NOT in the `install-tool` list, so the uv version cannot be pinned via
`scanSettings.versioning` — only `python` could be pinned if needed.
This probe does not require a Python version override beyond dynamic
detection, so no `.whitesource` is needed.

Note: if the operator wants to lock the uv binary to exactly
0.12.15 to reproduce the regression/fix boundary, they must install
uv 0.12.15 out-of-band before running the Mend scan. The uv version
is not pinnable via Mend's `install-tool`.

## Invocation context for the Mend UA

When the Mend UA invokes uv before scanning, it uses one of:

```sh
uv pip install --system -r requirements.txt
uv pip install --target /tmp/scan-target -r requirements.txt
```

Both forms were broken on pre-0.12.15 uv (regression introduced in
an earlier 0.12.x build). Post-0.12.15, both forms are accepted and
the install proceeds normally. Mend then reads the installed packages
via the pip-compatible lockfile path.

## Resolver note

uv flows through Mend's pip-compatible resolver path. The lockfile
is read directly; no uv CLI invocation is needed for lockfile-
driven detection. The install-command flag fix matters for the
UA's pre-step (which installs into a virtual env or system path
before scan), not for the lockfile parse itself. This probe's
`expected-tree.json` encodes what Mend SHOULD produce; a scan
with a pre-0.12.15 uv binary would produce an empty tree if the
pre-step is enabled.
